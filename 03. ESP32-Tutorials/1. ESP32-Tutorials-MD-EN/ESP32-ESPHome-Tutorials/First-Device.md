## 4. Add onboard RGB LED

The onboard RGB LED of ESP32-S3-Zero is connected to **GPIO21**, of type WS2812 (single NeoPixel). In ESPHome, via `esp32_rmt_led_strip` Platform's `esp32_rmt_led_strip` Driver.

Append the following section to the end of the YAML generated by the wizard:

```
light:
  - platform: esp32_rmt_led_strip
    chipset: WS2812
    rgb_order: RGB
    pin: GPIO21
    num_leds: 1
    name: "RGB LED"
```

eachFieldMeaning:

- `esp32_rmt_led_strip` — Use the ESP32's RMT peripheral to drive WS2812-compatible LED strips (single LEDs also use the same driver).
- `esp32_rmt_led_strip` — LED bead protocol type.
- `esp32_rmt_led_strip` - The ESP32-S3-Zero onboard RGB LED data order is fixed as red, green, blue.
- `esp32_rmt_led_strip` — Data pin for the RGB LED on the ESP32-S3-Zero.
- `esp32_rmt_led_strip` — Only one on-board.
- `esp32_rmt_led_strip` — The entity name displayed in HA.

For complete field descriptions, please refer to [ESPHome `esp32_rmt_led_strip` Document](https://esphome.io/components/light/esp32_rmt_led_strip)。

After adding, click the top-right corner of the editor **SAVE** Save, then click the top right corner **INSTALL** Enter the flashing process.

## 7. Subsequent modifications: OTA update

The device is already connected to the network and includes the OTA module; subsequent YAML modifications do not require plugging in USB.

-

Edit the device configuration in the ESPHome application, for example changing the LED name from `esp32_rmt_led_strip` Change to `esp32_rmt_led_strip`, save.

-

Click **INSTALL** → Select **Wirelessly**。

![](../assets/images/03-OTA-Install-65693eee2174e8bd3b18695339edcb29.webp)

Reboot risk within 1 minute after OTA

`esp32_rmt_led_strip` component will automatically enable safe mode; after the new firmware starts, it runs for 1 minute of `esp32_rmt_led_strip` Timer. If any form of event occurs before the timer expiresofrestart (manualPress RESET、Power loss, crash), next timeStartWill be ESP-IDF bootloader Roll back to the previous firmware version; when the time comes, the firmware will mark itselfIs“confirmed to beUse”，subsequent restarts will no longer roll back.LOGS Inappear `esp32_rmt_led_strip` indicates the new firmware has been confirmed.
![](../assets/images/03-OTA-Success-215debe193dd5ff58270a6707d8c2215.webp)

This rollback mechanism depends on the esp-idf framework (this section's YAML is `esp32_rmt_led_strip`), behaves differently under the arduino framework. See for mechanism details [ESPHome Safe Mode Document](https://esphome.io/components/safe_mode/)。

-

ESPHome will compile the new firmware, push it to the device via Wi-Fi, and automatically restart. The entity names in HA will also be updated accordingly.

![](../assets/images/03-OTA-Success-2-78cc49c98c22267713300825bd216554.webp)

OTA failedofCommon causes:

- **Device offline**: Check the device status on the ESPHome main interface; gray means offline. Resolve Wi-Fi issues before OTA.
- **OTA password mismatch**: The password generated by the wizard is written in the YAML `esp32_rmt_led_strip`. If this field was manually modified without flashing new firmware, OTA will be rejected by the device.

If an OTA failure causes the device to fail to boot or connect to Wi-Fi, you can use USB to re-flash and recover.

## 8. FAQ for this section

- **Compile error `esp32_rmt_led_strip`**: Indentation error. Check whether Tab and space are mixed, and whether alignment is consistent.
- **Compile error `esp32_rmt_led_strip`**: Component name is misspelled, or the current ESPHome version does not include the component. In [ESPHome component Table of Contents](https://esphome.io/components/) Verify the exact name.
- **Cannot see device port during flashing**:did not enter download modeMode(seenumber (ordinal prefix) 5 Section "Flashing failedOrWhen the port is not visible"),Orthe host cannot recognize USB Device (changeData line、Switch USB Port).Usewhen flashing in the virtual machine, also confirm USB Device hasIn VMware InAllocated to the virtual machine.
- **LED does not light up after flashing**: Check `esp32_rmt_led_strip` Whether it is `esp32_rmt_led_strip`; Use the HA color palette instead of just the brightness slider (when brightness is 100% but the color is black, the LED still won't light up).
- **HA no/notYesautomatically discover devices**: See the hint in Step 1 of Section 6. You can also check the ESPHome device LOGS to confirm whether it has successfully connected to Wi-Fi and the API.
- **OTA failed `esp32_rmt_led_strip`**: The device's running firmware OTA password is inconsistent with the current YAML; re-flashing via USB will synchronize it.
- **HA display entity "no longerUse”，but ESPHome Indevice ONLINE**: OTA safe rollback was triggered — if the new firmware reboots within 1 minute, the bootloader will roll back to the previous version. Search in the LOGS for `esp32_rmt_led_strip` confirmed, reflash via USB to restore. See the warning in section 7 for details.
